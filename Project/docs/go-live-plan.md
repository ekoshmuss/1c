# План перехода на рабочую базу и публикации в интернете

Статус на 24.11.2026: всё проверяется на **копии** базы (`vigruzki`). Рабочую базу пока не трогаем.

## Текущее состояние (копия)

| Что | Где |
|---|---|
| Расширение `LabStock` (HTTP-сервис `labstock`: `/ping`, `/meta`, `/stock`, `/receipts`) | база «Копия», Srvr=localhost; Ref=vigruzki |
| Публикация копии | IIS, `http://192.168.2.3:6536/vigruzki/` |
| Веб-интерфейс | `C:\LabStock\app` на сервере 192.168.2.3, `http://192.168.2.3:8080` |
| Склады | все, чьё наименование начинается с `018` или `023` (включая «018 КДЛ … (ПОСТ)» — оставить) |
| Норма 100% | последнее поступление (любой приход) на склад; админ может задать вручную |
| Вход на сайт | пользователь `admin` (роль admin), пароль задан на сервере |
| 1С-пользователь для сайта | временно «Админ» копии (в `.env`) |

## Шаги перехода (выполнить, когда проверка на копии закончена)

1. **Резервная копия рабочей базы** (`.dt`).
2. **Расширение в рабочую базу:** в Конфигураторе копии «Расширения конфигурации → LabStock → Конфигурация → Сохранить в файл» (`LabStock.cfe`),
   в Конфигураторе рабочей базы — «Добавить из файла», снять «Безопасный режим» не нужно, обновить БД.
3. **Пользователь 1С `web_api`** в рабочей базе: только чтение (без «Полных прав»), аутентификация 1С.
4. **Публикация рабочей базы** (`/new`, IIS порт 6536): включить «Публиковать HTTP-сервисы расширений по умолчанию».
   Проверить `http://192.168.2.3:6536/new/hs/labstock/ping` под `web_api`.
5. **`.env` сайта:** `ONEC_URL=http://192.168.2.3:6536/new/hs/labstock`, `ONEC_USER=web_api`, `ONEC_PASS=…`.
   Нормы, заданные вручную на копии (`data/norms.json`), перенесутся как есть.
6. **Автозапуск сайта:** `install-autostart.ps1` (от имени администратора).
7. **Поддомен + HTTPS** по `docs/domain-setup.md` (DNS-запись, IIS URL Rewrite + ARR, сертификат Let's Encrypt,
   `.env`: `HOST=127.0.0.1`, `TRUST_PROXY=1`, `COOKIE_SECURE=1`).
8. **Пользователи сайта** для лаборантов: `node users.js add <логин> viewer "ФИО"`.
9. Проверка с внешнего адреса, затем удалить временные данные доступа «Админ» из `.env`.

## Что понадобится от заказчика при переходе
- Время, когда можно обновить рабочую базу (вход в Конфигуратор).
- Доступ к DNS домена `gkib.kz` и к роутеру (проброс 443/80), либо контакт того, кто их администрирует.
- Имя поддомена (предложено `sklad.gkib.kz`).

# Настройка 1С для веб-интерфейса остатков

Цель: 1С по адресу `http://<IP или домен>/<имя публикации>/hs/labstock/...` отдаёт остатки в формате JSON.
Типовую конфигурацию не меняем, всё делаем в **расширении**.

---

## Этап 0. Проверка

1. Откройте «Справка → О программе» и запишите версию платформы и версию конфигурации.
   HTTP-сервисы в расширениях работают на платформе **8.3.11 и новее**.
2. Сделайте резервную копию базы: Конфигуратор → Администрирование → Выгрузить информационную базу (`.dt`).

## Этап 1. Создание расширения

1. Откройте **Конфигуратор** от имени администратора.
2. Выберите «Конфигурация → Расширения конфигурации → Добавить».
   - Имя: `LabStock`
   - Синоним: `Остатки для веб-интерфейса`
   - Префикс: `лаб_`
   - Назначение: **Дополнение**
3. Выделите расширение и нажмите «Конфигурация» (откроется дерево расширения).

## Этап 2. HTTP-сервис

1. В дереве расширения откройте «Общие → HTTP-сервисы → Добавить».
   - Имя: `лаб_Склад`
   - Корневой URL: `labstock`
2. На вкладке «Шаблоны URL» создайте три шаблона. Внутри каждого добавьте метод `GET`:

| Шаблон | Имя шаблона | Метод | Обработчик |
|---|---|---|---|
| `/ping`  | Ping  | GET | `лаб_PingGET`  |
| `/meta`  | Meta  | GET | `лаб_MetaGET`  |
| `/stock` | Stock | GET | `лаб_StockGET` |

   Имя обработчика впишите в свойство «Обработчик» метода **вручную, точно как в таблице**.
3. Откройте модуль сервиса (кнопка «Открыть модуль») и **замените всё содержимое** кодом из файла
   `Project/1c-extension/labstock_module.bsl`.
4. Выполните «Конфигурация → Обновить конфигурацию базы данных (F7)» в окне расширения.

## Этап 3. Свойства расширения в базе

1. Запустите 1С:Предприятие под администратором.
2. Откройте «Все функции → Стандартные → Управление расширениями конфигурации».
3. У расширения `LabStock`:
   - «Активно»: включено.
   - «Безопасный режим»: можно **оставить** включённым, расширение только читает данные.
   - «Защита от опасных действий»: оставить по умолчанию.

## Этап 4. Публикация HTTP-сервисов

Публикация базы уже есть, нужно разрешить в ней HTTP-сервисы расширений.

**Вариант А, через Конфигуратор** (запускать на компьютере с веб-сервером, от имени администратора):

1. Откройте «Администрирование → Публикация на веб-сервере».
2. Выберите **существующую** публикацию (то же имя и каталог).
3. На вкладке «HTTP сервисы» включите:
   - «Публиковать HTTP сервисы по умолчанию»
   - **«Публиковать HTTP сервисы расширений по умолчанию»**
4. Нажмите «Опубликовать» и перезапустите веб-сервер (Apache: служба Apache2.4; IIS: `iisreset`).

**Вариант Б, вручную.** В каталоге публикации откройте файл `default.vrd` и добавьте (или исправьте) строку внутри `<point ...>`:

```xml
<httpServices publishByDefault="true" publishExtensionsByDefault="true"/>
```

Затем перезапустите веб-сервер.

## Этап 5. Технический пользователь

1. В 1С:Предприятии откройте «Администрирование → Настройки пользователей и прав → Пользователи → Создать».
   - Имя: `web_api`
   - Аутентификация 1С: включена, задайте сложный пароль.
   - Права: **только чтение** (типовой профиль или роль просмотра бухгалтерских данных).
     Не давайте «Полные права».
   - Снимите флажок «Показывать в списке выбора».
2. Сохраните логин и пароль: они понадобятся для настройки backend.

> Каждый запрос к HTTP-сервису ненадолго занимает лицензию 1С. Backend будет кэшировать данные, поэтому нагрузка небольшая.

## Этап 6. Проверка в браузере

Откройте по очереди адреса и войдите под пользователем `web_api`:

1. `http://<IP или домен>/<имя публикации>/hs/labstock/ping`
   Ожидается ответ `{"status":"ok", ...}`.
2. `http://<IP или домен>/<имя публикации>/hs/labstock/meta`
   Это описание регистров, счетов и справочников. **Сохраните ответ в файл `Project/docs/meta.json`.**
3. `http://<IP или домен>/<имя публикации>/hs/labstock/stock`
   Остатки по счетам `13…` на сегодня. Можно указать дату и счёт: `.../stock?date=2026-11-01&account=1310`.
   Пример ответа сохраните в `Project/docs/stock-sample.json`.

Если в ответе ошибка 404, значит HTTP-сервисы расширений не опубликованы (этап 4).
Ошибка 401 означает неверный логин или пароль, 500 — ошибку в запросе (текст ошибки будет в ответе).

## Этап 7. Сеть и безопасность

- Адрес `hs/labstock` должен быть доступен только с компьютера, где будет работать backend: ограничьте его брандмауэром или правилом веб-сервера.
- Если доступ идёт через домен из интернета, используйте **HTTPS**.
- Никогда не храните пароль `web_api` в GitHub. Он будет лежать в файле `.env`, который исключён из репозитория.

## Что прислать для следующего шага

1. Файл `meta.json` (ответ `/meta`).
2. Файл `stock-sample.json` (ответ `/stock`).
3. Названия счетов и складов, на которых учитываются реагенты и медикаменты.

По этим данным я точно настрою запрос (регистр, счета, субконто «Номенклатура» и «Склад/МОЛ») и сделаю backend.

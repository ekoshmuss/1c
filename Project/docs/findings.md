# Что известно о базе 1С (осмотр 23.11.2026)

- Адрес веб-клиента: `http://1s.gkib.kz/new/ru_RU/` (доступен только из сети учреждения; из интернета домен не находится).
- Конфигурация: **«Бухгалтерский учет для государственных предприятий Казахстана», редакция 2.0** (БГП, не БГУ).
- В базе есть отдельный раздел **«Учет медикаментов»**:
  - документы: оприходование, требование-накладная, перемещение, списание, инвентаризация, комплектация медикаментов;
  - справочники: Номенклатура, **Серии медикаментов**, **Склады (места хранения)**, Пациенты;
  - отчёты: «Ведомость по учету медикаментов», **«Остатки медикаментов по сериям и срокам годности»**, «Контрольная ведомость медикаментов»;
  - интеграция с КМИС и маркировкой ЛС (ИС ЦЭДМ).
- Вывод: остатки для веб-интерфейса, скорее всего, нужно брать из **регистра накопления раздела «Учет медикаментов»** (склад + номенклатура + серия + срок годности), а не из бухгалтерских счетов. Точное имя регистра покажет `/hs/labstock/meta`.
- Это открывает дополнительную возможность: показывать в интерфейсе **истекающие сроки годности**.

## Работа на сервере 1С (23.11.2026, RDP 192.168.2.3)

- Остатки медикаментов хранятся в регистре накопления **УчетМедикаментов**:
  - измерения: Организация, ИсточникФинансирования, КлассификацияРасходов, **Медикамент**, **СерияМедикаментов**, СчетУчета, **Склад**, СтруктурноеПодразделение;
  - ресурсы: **Количество**, **Сумма**.
- Медикаменты — это справочник «Номенклатура» с признаком «ЯвляетсяМедикаментом», серии — справочник «СерииМедикаментов».
- В базе уже есть HTTP-сервисы КМИС (GetDrugBalance и др.) — наш сервис отдельный, их не трогаем.
- В базе **«Копия»** (Srvr=localhost; Ref=vigruzki) создано расширение **LabStock** (префикс `лаб_`, «Дополнение»)
  с HTTP-сервисом `лаб_Склад` (`labstock`): `/ping`, `/meta`, `/stock`. Синтаксическая проверка пройдена, БД обновлена.
- Публикация `vigruzki` (IIS, `C:\inetpub\wwwroot\vigruzki\`): включено «Публиковать HTTP сервисы расширений по умолчанию».
- **Проблема:** `http://localhost/` на сервере не открывается — IIS на этом сервере, похоже, не отвечает на порту 80.
  Нужно выяснить, где работает веб-сервер, через который открывается `1s.gkib.kz/new`.

## Проверка HTTP-сервиса (23.11.2026) — РАБОТАЕТ

- Веб-сервер IIS работает на порту **6536**. Копия базы: `http://192.168.2.3:6536/vigruzki/`.
- Вход в HTTP-сервис — базовая авторизация (логин/пароль пользователя 1С).
- `GET /vigruzki/hs/labstock/ping` → `{"status":"ok", ...}`.
- `GET /vigruzki/hs/labstock/stock` → **2530 строк** (остатки на текущую дату).
  - Поля строки: `Склад, Код, Наименование, Группа, Серия, ЕдиницаИзмерения, СрокГодности, Количество, Сумма`.
  - 34 склада (места хранения). Лаборатории: **«018 КДЛ ст. фельдшер лаборант»** (507 позиций) и **«023 ЦБЛ фельдшер лаборант»** (216 позиций).
  - Срок годности заполнен у 1925 строк (у остальных `0001-01-01` = не указан).
  - 41 строка с **отрицательным** остатком — веб-интерфейс должен их подсвечивать отдельно.
- Исправление в коде: сортировка перенесена из запроса в `Таблица.Сортировать(...)` (1С не разрешает УПОРЯДОЧИТЬ ПО представлению).

## Поддомен sklad.gkib.kz (24.11.2026)

- DNS домена gkib.kz обслуживается в **консоли ps.kz** (console.ps.kz → Домены → Управление DNS → gkib.kz.), NS ns1/ns2/ns3.ps.kz.
  Зона в Plesk (srv-plesk26.ps.kz) **не используется** NS-серверами — запись `sklad` там добавлена по ошибке, на работу не влияет.
- Добавлена запись `sklad.gkib.kz. A 194.76.125.70` (как у `1s.gkib.kz`). NS ps.kz отдают её сразу; публичным DNS нужно до ~1 часа.
- Роутер: внешний 194.76.125.70:80 → сервер IIS :6536 (а 443 → :3656, сертификат самоподписанный).
- На сервере установлены IIS **URL Rewrite 2.1** и **ARR 3.0** (подписи Microsoft проверены), включён прокси ARR.
- Сайт IIS **«LabStock sklad»**: `http *:6536:sklad.gkib.kz`, папка `C:\LabStock\iis` (web.config — обратный прокси на 127.0.0.1:8080), пул `LabStockSklad`. Скрипт: `app/setup-sklad-iis.ps1`.
- `.env`: `TRUST_PROXY=1`; в `auth.js` IP клиента берётся из последнего значения X-Forwarded-For (его добавляет ARR).
- Проверка: через 194.76.125.70:80 с Host sklad.gkib.kz → 200; 1С `/new` → 200 (не затронута).

## HTTPS для sklad.gkib.kz (24.11.2026) — РАБОТАЕТ

- win-acme 2.4.1 (`C:\LabStock\win-acme`, SHA256 сверен с GitHub, подпись SignPath) выпустил сертификат **Let's Encrypt** для sklad.gkib.kz (до 22.02.2027).
- Проверка http-01 через файл в `C:\LabStock\iis\.well-known\acme-challenge` (путь исключён из прокси в web.config).
- IIS: привязка `https *:3656:sklad.gkib.kz` (SNI), сертификат в хранилище WebHosting. Привязку 1s.gkib.kz не трогали.
- Автопродление: задача планировщика **«win-acme renew (acme-v02.api.letsencrypt.org)»**, ежедневно 09:00, продление после 18.01.2027.
- Включено перенаправление http → https (302) для sklad.gkib.kz. Cookie сессии получает Secure автоматически (X-Forwarded-Proto=https).
- Скрипт: `app/setup-sklad-https.ps1`.
- Сертификат, выпущенный в Plesk для поддомена sklad, на сервере не используется (Plesk-поддомен sklad можно удалить).
